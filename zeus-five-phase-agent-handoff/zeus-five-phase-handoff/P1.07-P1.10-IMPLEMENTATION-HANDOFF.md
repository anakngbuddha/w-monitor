## Compatibility and operator actions

1. Back up and verify restore before any schema or production rollout. New receipt/budget tables and indexes are additive; acceptance, data insertion and both budgets share a transaction. Test both backends before applying to real evidence.
2. Upgrade the Hub before agents. Agents now use `POST /api/v1/ingest/batches`. The legacy single-row route accepts bound machine tokens only and derives stable legacy identities. Read/admin/legacy-all tokens cannot ingest. Legacy client-supplied foreign tenant/server fields are rejected, not silently reassigned.
3. The supported delivery window is 30 days, with a one-minute future tolerance. Receipt cleanup retains at least 32 days from receipt. Old/corrupt/invalid queues need reviewed recovery, never silent deletion or blind replay. Full/quarantined queues count toward the local cap.
4. Defaults: 20,000,000 accepted rows / 20 GiB per tenant UTC day; 250,000 rows / 256 MiB per agent UTC day. Set tenant and agent row/byte limits consistently. The pre-auth peer bucket is intentionally larger than the authenticated agent bucket for reverse-proxy fleets. These are initial policies, not measured support claims.
5. Use one absolute protected `-config` or `WMONITOR_CONFIG` file, otherwise the machine config path. Explicit flags beat environment; environment beats file values. Use UTF-8 without BOM. No current-directory or executable-directory config fallback. Windows machine config and its parent require protected SYSTEM/Administrators/service-identity ACLs; Linux files must not grant group/other access.
6. No automatic config-key/CSV registration or revival. Bootstrap with explicit `-new-admin-token`, `-add-client` and `-new-enroll-code`. Non-transactional legacy CSV credential import is disabled pending a reviewed migration; existing opaque-tenant migration remains explicit. No live credential was probed, revoked or rotated by this work.
7. Remote PostgreSQL must use verified TLS, normally `sslmode=verify-full`; `require` and `verify-ca` are insufficient. Direct local test fixtures may use loopback plaintext. PostgreSQL disk capacity must additionally be constrained by the database operator; a SQLite file budget cannot measure a remote service.
8. Fresh-install scripts no longer accept token/DSN values as arguments and will not silently stop/replace existing services or unrelated sysmon processes. Per-user hidden startup installation is disabled. Existing installs require a reviewed maintenance-window upgrade. A supplied SHA-256 is not publisher signing; signed packaging remains a release gate.
9. `/api/health` is liveness only and reveals no global customer freshness/alerts. `/api/ready` checks dependencies. `/metrics` requires a real admin credential in Hub mode even behind a loopback proxy. Sessions are intentionally replica-local: restart or a different replica can require login again; use sticky routing until a reviewed shared-session store is introduced.
